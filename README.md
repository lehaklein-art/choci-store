# חלון הראווה של צ'וקי

האתר החדש (Next.js על Sevalla) **בונה בעצמו** כל עמוד בחנות — באותו מבנה ועיצוב כמו האתר המקורי.
וורדפרס/ווקומרס (choci.kinsta.cloud) נשאר **המחסן**: מוצרים, מחירים, מלאי, הזמנות, עגלה ותשלום.

## איך זה עובד
1. בכל כתובת, האתר מבקש מוורדפרס **נתונים גולמיים** (`?choci_api=1`) — מוצרים, סינונים וספירות, מחירים, תמונות, טקסטים.
   את הנתונים מחזיר התוסף לקריאה בלבד `wp/choci-headless-api.php` (מותקן ב-`wp-content/mu-plugins`).
2. הקוד כאן בונה מהם את העמוד:
   - `lib/archive.js` — קטגוריות, חנות, חיפוש (כרטיסי מוצר, סינונים, מיון, סרגל מחיר, עימוד, טיפ, מבצעים, "משלימים").
   - `lib/product.js` — עמוד מוצר (גלריה, וריאציות, הוספה לסל, כשרות, טיפ, מתכון, מפרט, שאלות, משלימים).
   - `lib/singular.js` — דף הבית (רצועות מוצרים ומתכונים), עמודי תוכן, מתכונים, ארכיון מתכונים.
   - `lib/document.js` + `lib/chrome.js` — מעטפת העמוד: ראש, הדר, פוטר, עגלה צפה, מועדפים, מועדון, נגישות, תפריט נייד.
3. ההתנהגות בדפדפן: `public/site/chrome.js`, `public/site/product.js`, `public/choci-lite.js` — בלי jQuery.
   העיצוב: `public/site/*.css`. ה-CSS הנוסף שנשמר בהגדרות העיצוב של וורדפרס מגיע כנתון ונשמר כקובץ.
4. עמוד מוכן נשמר בזיכרון ובקצה (Cloudflare) ומתרענן ברקע (`REVALIDATE`, ברירת מחדל 10 דקות).

## מה עובר ישירות לווקומרס
עגלה, קופה, החשבון שלי, פעולות AJAX של העגלה/מועדפים/מועדון, טפסים, משתמשים מחוברים, קבצים ותמונות.

## משתני סביבה
`WC_URL` (כתובת המחסן), `REVALIDATE` (שניות), `ALLOW_INDEX=1` (לאפשר לגוגל — רק אחרי המעבר לדומיין).

## כלי בדיקה
`/orig-check/<כתובת>` מציג את העמוד המקורי מוורדפרס באותו דומיין, להשוואה אוטומטית מול העמוד החדש.

`lib/wp.js` — השיטה הקודמת (עמוד מוכן מוורדפרס), נשארת רק כגיבוי לעמוד שהבנייה החדשה לא מכירה.
תיקיית `prototype/` — אב-טיפוס ישן, לא פעיל.
